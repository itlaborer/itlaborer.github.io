# 让 AI 别再写十年前的弹窗：现代 Web 指南实测

## 一、结论先行：它调整的是代理的上下文

> 一句话结论：Modern Web Guidance 1.0 是 Chrome、Edge、Firefox、MDN 联合维护的一套「给 AI 编程代理用的 Web 平台知识库 + 离线命令行工具」，2026 年 11 月 10 日发布，代码 Apache-2.0、指南 CC-BY 4.0。

读完源码又在本机把命令跑了一遍，才确认这套东西是按需喂给代理的浏览器知识。

| 常见理解 | 实际情况 |
|---|---|
| 一份新的前端规范 | 可检索的知识库，由代理按需取用 |
| 一个运行时框架或库 | npm 包只提供命令行与 skill 指令，不进产物代码 |
| 给开发者看的文档站 | 主要读者是 AI 代理，用来注入上下文 |
| 需要联网调模型接口 | 语义检索本地完成，离线且无密钥 |

判断依据是发布仓里的 skill 指令与 `package.json` 的 `bin` 指向。入口是一个 `.mjs` 命令行脚本，`SKILL.md` 把「先检索后写码」写成强制流程。

📌 换句话说，这件事的落点在模型的输入侧。模型没变，喂给它的那一段上下文变了。

## 二、代理为什么总写出旧代码

| 现象 | 根因 | 后果 |
|---|---|---|
| 让代理写弹窗，得到一堆 div 加绝对定位加滚动监听 | 训练语料里遗留代码占比高 | 本该由原生 HTML 与 CSS 解决的事，写成臃肿脚本 |
| 知道某个接口存在，却写不出生产可用实现 | 缺少密集的现代实现范式 | 无障碍、焦点管理、退出动画、降级全靠猜 |
| 不敢用新特性，或者用了却没有降级 | 兼容性数据随浏览器版本变化，训练快照跟不上 | 要么过度保守，要么线上出兼容问题 |

项目给出 3 条产品原则：优先平台级接口，这类接口自带无障碍与性能；给轻量回退，避免重型兼容包；只保留经评测证明「模型本来不会」的内容，主动剪枝模型已知的建议以节省上下文。

第 3 条最容易被忽略。指南不是越多越好，模型本来就会的写法反而会占掉宝贵的上下文窗口。

## 三、它由什么组成

| 层 | 实测规模 |
|---|---|
| 发布仓 | 265 个文件，`skills/` 下 234 个；2 个 skill 包约 205 与 175 tokens |
| 源码仓 | 2,400 个文件，其中 `guides/` 1,676、`src/` 603 |
| 指南库 | README 标注 250 个 Web 特性：CSS 与布局 140、HTML 与 DOM 36、JS 与 API 74 |
| 发布仓实有指南 | 209 个 md，按 17 类归档，最多的几类是交互 40、性能 26、组件 22、视觉 22、表单 19 |
| 运行环境 | Node 22 及以上，本机为 22.22.2、npm 10.9.7 |

数量口径要说明：250 是特性数，209 是发布仓的 md 文件数，另有报道称「203 篇用例指南」。三者并不矛盾，引用时要指明是哪一口径。

6 个重点领域：进出场动画与视图过渡、容器查询与现代 CSS、性能与交互响应指标、弹出层与表单、无障碍、浏览器内置 AI。

## 四、一份指南的密度才是价值所在

我实取了 `animate-to-from-top-layer`，10.7 KB、244 行。它是一份可直接落地的工程文档：

| 段落 | 内容 |
|---|---|
| 实现步骤 | 4 步：`transition-behavior: allow-discrete`、`overlay`、`@starting-style` 进场、`::backdrop` 动画 |
| 完整示例 | 含减弱动效偏好的分支，并注明 `@starting-style` 必须放在打开状态选择器之后 |
| 约束清单 | `MANDATORY` 与 `DO NOT`：过渡列表必须含 `overlay`；`allow-discrete` 不能写进 `transition` 简写；`@starting-style` 不用于退场 |
| 兼容与降级 | 每个特性标 Baseline 状态与具体版本，例如 `@starting-style` 于 2024 年 8 月 6 日进入 Newly available |
| 已知引擎缺陷 | 记录 Firefox bug 1882408：特性探测返回真，实际却不过渡离散属性，元素退场会瞬间消失；并给出探针检测代码 |

最后一条最说明问题。版本、引擎缺陷、探测代码、无障碍约束、降级边界，恰是模型语料里最稀疏的部分。

另一份 `navigation-drawer` 有 20.8 KB，用顶层 `dialog` 与 `popover` 实现侧滑抽屉，附 4 组降级，每条都标 Baseline 日期。相比之下，「用某个属性做动画」这类知识模型本来就会，指南不会为它多花 token。

## 五、怎么用：4 步强制流程

skill 指令把调用写成流程，并标明 MANDATORY：

| 步骤 | 动作 | 关键约束 |
|---|---|---|
| 检索 | `search` 用 2 至 5 个动作型词描述用户可见能力 | 去掉框架名与业务名词，多特性任务拆多次 |
| 取回 | `retrieve` 按 id 取全文，并取一条学科总览 | 输出超 9.5 KB 会落临时文件，要求完整读取 |
| 自检 | 写完回查指南中的现代模式、必要降级与约束 | 不得强行塞入未要求的特性 |
| 披露 | 回复末尾逐条列明用了哪些 id、避开了什么坑 | 一条没用也要写明查过什么 |

```bash
npx -y modern-web-guidance@latest search "light dismiss dialog"
npx -y modern-web-guidance@latest retrieve "animate-to-from-top-layer,css"
npx -y modern-web-guidance@latest list
```

查询词写法有讲究。写 `light dismiss dialog`，不写业务化的「关闭设置弹窗」。前者描述用户可见能力，后者会把检索带进业务名词的噪声里。

触发边界同样明确：HTML、CSS 与客户端脚本任务强制先执行，弹窗、暗色模式、表单校验、动画、无障碍都在内；后端接口、基础设施、构建工具配置不触发。整库遗留扫描另有适用范围，只在明确要求开放式现代化时才用。

检索是离线 embedding 加 BM25，零依赖、无网络调用、无 API Key。`npx @latest` 只为保证内容不过期，首次取包需要联网，检索本身完全本地。

### 兼容性怎么定

默认目标是 Baseline Widely available：广泛可用的直接用，非广泛可用必须按指南给降级。项目建议把自定义策略写进 `AGENTS.md`，例如「允许 Newly available，但降级代码不超过 20 行且无外部依赖」。

实验性指南默认锁住。试验特性与近 3 个月仍在稳定中的特性可以检索到，取回全文需要显式开关，或在项目根 `.mwgrc` 写配置：

```json
{
  "allowOriginTrials": true,
  "allowVolatileFeatures": true
}
```

区分纯增强与关键行为是这里最实用的一条。推测性预加载这类，旧浏览器静默忽略即可；对话框控制与网络信标必须写低开销回退。降级优先少于 50 行的定制实现或按需加载的 polyfill。

## 六、本机实跑：3 条命令，一个反直觉结果

| 命令 | 结果 |
|---|---|
| `search "animate a dialog modal backdrop"` | 返回 10 条，首条即目标指南，另有轻量关闭、声明式弹层等 |
| `retrieve "animate-to-from-top-layer"` | 输出 10.7 KB，因超阈值写入临时文件并要求完整读取 |
| `legacy-scan . --json` | 对含手写固定定位弹窗与滚动监听的最小样例，0 命中 |

```json
{"totalFindings": 0, "activeRuleCount": 35, "activeGuideCount": 33,
 "note": "No legacy patterns found across 33 guides (35 rules; ~20% of the guidance corpus)."}
```

⚠️ 这个 0 命中来自首版刻意收窄的范围。静态规则只有 35 条、覆盖 33 篇指南，约占语料 20%，且依赖确定性模式匹配。

样例里肉眼可见的旧写法没被扫出来，说明它不能替代人工审计或代理逐条推理。官方也说明，后续才会扩展「让代理直接推理代码」的审计方式。

## 七、效果数据怎么读

评测闭环比分数本身更值得看。它在完整示例应用上给真实开发指令且故意不点名接口，由 Playwright 判分器检查源码模式、计算样式、运行时行为与无障碍状态。金标准方案须 100% 通过，未改动的基线须 0% 通过，再用多代理交叉校准。

提升空间定义为「100% 减去无引导通过率」，模型本来就会的建议主动剪枝。README 快照取自 2026 年 11 月 8 日，约 215 个任务、1,800 条断言：

| 代理 | 无引导 → 有引导 | 提升 |
|---|---|---|
| Claude Code | 57% → 88% | +31 个百分点 |
| Codex CLI | 54% → 82% | +28 个百分点 |
| Antigravity CLI | 58% → 94% | +36 个百分点 |

⚠️ 口径提醒：以上均为项目方与合作方自报，缺少第三方独立验证。生产案例同理，MetaMask 在 5 周约 480 个 PR 上跑审查机器人，推动修复 43 项发现。引用时别写成「实测提升」。

## 八、落地建议与仍存的边界

手上有一个原生 JS 与 CSS 写的新标签页项目，弹窗、暗色模式、滚动、表单全在触发范围内。按「先摸底、再取指南、最后验收」排了一条 SOP：

- ✅ 先在前端目录跑 `legacy-scan <前端目录> --json`，把静态命中当线索
- ✅ 对具体改造点走 `search` 加 `retrieve`，写前注入、写后自检
- ✅ 在 `AGENTS.md` 写明本项目的浏览器兼容策略
- ✅ CI 若挂命令，权限白名单只放行 `npx -y modern-web-guidance@latest *`，不放行裸 `npx *`
- ✅ 生产环境设 `DISABLE_TELEMETRY=1`。遥测默认开启，采集安装计数、代理名、取用 id 与查询词，不采原始提示词
- ❌ 不要给后端目录挂这套流程，Go 服务不在触发范围内
- ❌ 不要把扫描 0 命中当成「代码已现代化」

已确认的部分：离线检索、命令行为、指南密度、扫描覆盖率、评测口径，均来自官方仓库与本机实跑。

仍待验证的部分：

| 项 | 状态 |
|---|---|
| 在实际代理里启用后，生成质量的提升幅度 | 【需补充】本次未安装到代理、未做对照实验 |
| 框架项目的适配成本（属性透传、服务端渲染守卫、实例 id 生成） | 【需补充】指南按原生 HTML/CSS/JS 编写 |
| 中文场景与国内浏览器内核的兼容表现 | 【需补充】兼容数据基于 Baseline 与主流引擎 |
| 遥测开关在受限网络下的实际行为 | 【需补充】 |

「专家写短指南 + 兼容数据 + 可检索索引 + 自动评测剪枝」这套结构，和本号把每次踩坑反哺进写作流程是同一个思路，只是它多了 Baseline 数据与判分闭环。工具会过期，这类沉淀方式不会。
